# Архитектура

Один npm-пакет на TypeScript (ESM), Node.js 24, один процесс. Без workspaces и отдельных сервисов.

## Слои

| Каталог | Назначение |
| --- | --- |
| `src/app` | Точка входа: чтение `process.env`, `process.argv` и `.env`, конфигурация, композиция зависимостей, CLI, запуск и остановка процесса. |
| `src/domain` | Предметные типы и чистые правила: даты, расписание, профиль, библиотека, премьеры, планирование событий календаря. |
| `src/application` | Сценарии и интерфейсы внешних зависимостей (`ports.ts`): интервью, подборка, библиотека, отслеживание, синхронизация календаря, доставка, планировщик, `/status`. |
| `src/adapters` | Реализации интерфейсов: Telegram (grammY), DeepSeek (`openai`), TMDB (`fetch`), Google Calendar (`fetch` + `google-auth-library`), SQLite (`node:sqlite`). |
| `src/prompts` | Markdown-инструкции для модели: `interview.md`, `ranking.md`. При сборке копируются в `dist/prompts`. |

## Направления зависимостей

```
app ──► adapters ──► application ──► domain
 │                        ▲
 └────────────────────────┘
```

Правила в [.dependency-cruiser.cjs](.dependency-cruiser.cjs), проверка — `npm run check:deps`:

| Правило | Запрет |
| --- | --- |
| `domain-is-pure` | `domain` импортирует только `domain`: ни других слоёв, ни Node API, ни npm-пакетов. |
| `application-not-to-outer-layers` | `application` не импортирует `app` и `adapters`. |
| `application-not-to-integration-sdk` | Из npm-пакетов `application` может использовать только `zod`; `node:sqlite` запрещён. |
| `grammy-only-in-telegram-adapter`, `openai-only-in-deepseek-adapter`, `google-auth-only-in-google-adapter`, `sqlite-only-in-sqlite-adapter` | SDK используется только своим адаптером. |
| `only-app-imports-app` | `app` — корень композиции, его никто не импортирует. |
| `no-dev-dependencies-in-src` | Production-код не импортирует dev-зависимости. |
| `no-circular` | Циклические зависимости. |
| `no-unresolvable` | Неразрешимые импорты. |

Импорты только типов тоже учитываются (`tsPreCompilationDeps`), поэтому типы SDK не просочатся в `domain` и `application` через `import type`.

Конфигурация передаётся явно: `process.env` и `process.argv` читает только `src/app/main.ts`, остальной код получает значения параметрами.

## Точки входа

- `src/app/main.ts` — загрузка `.env`, запуск `runCli`, сигналы `SIGTERM`/`SIGINT`, код завершения.
- `src/app/cli.ts` — команды `help`, `doctor [--network]`, `run`; остальное — ошибка использования (код 2).
- `src/app/settings.ts` — описание настроек, проверка через Zod, `readConfig` для запуска, список секретов для маскировки журнала.
- `src/app/run.ts` — долгоживущий процесс: монопольно открытая база, адаптеры, `composeApplication`, планировщик и long polling.
- `src/app/compose.ts` — связывание сценариев с адаптерами; его же используют сквозные тесты Telegram.

Собранная точка входа — `dist/app/main.js`; Docker-образ запускает её с командой `run`.

## AI-пайплайн

Модель не обращается к сети и не меняет состояние. Код:

1. **Интервью.** Передаёт модели диалог, черновик и подтверждённые сериалы; получает обновлённый черновик, упомянутые названия и следующий вопрос. Названия разрешаются поиском TMDB, пользователь выбирает карточку — ID назначает код. Не больше четырёх уточнений, затем итог на подтверждение.
2. **Подборка.** Собирает кандидатов из трёх источников (`/tv/{id}/recommendations` для понравившихся, `discover` по жанрам вышедших сериалов с не меньше чем 50 оценками, `discover` по датам эфира на 180 дней с проверкой даты сезона), исключает просмотренные, отклонённые, сохранённые, отслеживаемые, уже предложенные и сериалы профиля, по очереди берёт из источников до 60 кандидатов с описанием. Модель возвращает до трёх `tmdbId + explanation`; ID вне переданного набора и повторы отклоняются (`ModelContractError`). Карточки собирает код из данных каталога.

JSON Output DeepSeek проверяется Zod в адаптере; невалидный ответ модель исправляет один раз, повторная ошибка, пустой ответ и тайм-аут завершают операцию.

## Состояние и надёжность

SQLite (`node:sqlite`), WAL, внешние ключи, схема версионируется `PRAGMA user_version` (`src/adapters/sqlite/database.ts`). Транзакции короткие, сетевые вызовы — вне транзакций. В режиме `run` база открывается с `locking_mode = EXCLUSIVE`: второй процесс не запустится, поэтому резервное копирование — при остановленном контейнере.

- **Профиль.** Подтверждённый профиль и незавершённое интервью хранятся раздельно: прежний профиль действует до подтверждения нового.
- **Библиотека и подписки** независимы: просмотренный сериал можно отслеживать.
- **Подборка** сохраняется вместе с исходящими сообщениями до отправки; ключ запуска (`manual:…`, `weekly:<срок>`) уникален, поэтому повтор не вызывает модель заново.
- **Исходящие сообщения** — очередь с ключом логической доставки; отправляются по порядку, при ошибке сообщение ждёт повтора с растущей задержкой и не пропускается. При неоднозначном сетевом результате Telegram возможен редкий повтор сообщения.
- **Премьеры.** Хранится последняя подтверждённая дата каждого сезона (`tmdbId + seasonNumber`). Дата берётся из `air_date` сезона, сезон 0 исключён; для будущих сезонов и сезонов без даты запрашивается `/tv/{id}/season/{n}` без кэша. Ошибка источника не меняет сохранённые даты. Изменения одной проверки собираются в одно сообщение; «премьера сегодня» — один раз в день и только в день премьеры.
- **Календарь.** Желаемое состояние события (`create`/`update`/`delete`) и его ID сохраняются до сетевого вызова. ID — `ss<tmdbId>s<сезон>g<поколение>`; повтор использует тот же ID, конфликт создания разрешается чтением события и обновлением. После удаления поколение растёт. Изменяются только события с меткой `series-scout` и ключом премьеры в `extendedProperties.private`. События — на весь день, без занятости, с исходной календарной датой. Прошедшие события не удаляются.
- **Планировщик.** Такт раз в минуту. Срок задания хранится в базе; после простоя просроченное задание выполняется один раз, следующий срок считается от момента запуска. Срок пересчитывается при смене расписания в настройках. На каждом такте — доставка очереди и незавершённые операции календаря.
- **Последовательность.** Операции одного типа (`premiere-check`, `recommendations`, `calendar`, `delivery`) выполняются строго друг за другом в процессе. Обновления Telegram grammY обрабатывает последовательно.
- **Повторы.** TMDB и Google: до трёх попыток для сети, тайм-аута, 429 и 5xx с учётом `Retry-After`. Ошибки авторизации не повторяются. Кэш ответов TMDB для подборок — 24 часа; проверка премьер и подписка обращаются к источнику напрямую.
- **`/status`** показывает сохранённые результаты последних обращений к каждому сервису, заданий и размеры очередей, сам сервисы не опрашивает.

## Telegram

Проверка владельца — первый middleware: обновления не от `TELEGRAM_OWNER_ID` или не из личного чата отбрасываются до чтения данных и внешних запросов. Действия кнопок идемпотентны; после одноразовых действий (выбор карточки, подтверждение профиля, оценка) клавиатура сообщения убирается. `callback_data` кодируется компактно (`w:<id>`, `r:<id>:l` и т. п.), устаревшая кнопка получает подсказку.

## Сборка

- Исходники запускаются Node.js 24 напрямую (type stripping). `erasableSyntaxOnly` запрещает синтаксис, который требует преобразования: `enum`, `namespace`, parameter properties.
- Импорты пишутся с расширением `.ts`; `rewriteRelativeImportExtensions` заменяет его на `.js` при сборке.
- `tsconfig.json` проверяет `src`, `tests` и `vitest.config.ts` без генерации файлов; `tsconfig.build.json` собирает только `src` в `dist`.
- `npm run build` копирует промпты в `dist/prompts` и запускает `dist/app/main.js --help`, чтобы проверить собранный JavaScript, а не только исходники.
- TypeScript зафиксирован на 6.x: dependency-cruiser 18 поддерживает TypeScript `<7.0.0` — ему нужен классический JS API компилятора, которого нет в пакете TypeScript 7.
