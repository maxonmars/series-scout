# Series Scout

Персональный Telegram-бот для выбора сериалов и отслеживания премьер новых сезонов. Рассчитан на одного владельца.

## Назначение

- Интервью о предпочтениях и персональные рекомендации.
- Обратная связь по рекомендациям и список «Хочу посмотреть».
- Подписки на новые сезоны и периодическая проверка оригинальных дат премьер.
- Синхронизация премьер с отдельным Google-календарём.

AI работает в явном пайплайне: модель формирует профиль предпочтений и ранжирует реальных кандидатов из TMDB. Получение данных и внешние действия (запросы к TMDB, записи в календарь, сообщения в Telegram) выполняет код приложения.

## Текущее состояние

Реализован технический фундамент:

- CLI с командами `help` и `doctor`;
- `doctor` — локальная диагностика версии Node.js и настроек, без сетевых запросов;
- сборка, проверки, архитектурные границы слоёв, Docker-образ и CI.

Работа бота, рекомендации, подписки, интеграции с Telegram, DeepSeek, TMDB и Google Calendar, хранилище SQLite и планировщик **ещё не реализованы**. Ни одна команда не обращается к внешним сервисам.

## Требования

- Node.js 24 (точная версия — в [.nvmrc](.nvmrc); с nvm: `nvm use`).
- npm 11.
- Docker с Compose — только для запуска в контейнере.

## Установка

```bash
npm ci
```

```bash
cp .env.example .env
```

Пояснения к каждой настройке — в [.env.example](.env.example). Пустое значение считается незаданным. `.env` читается из рабочего каталога при запуске, если файл есть; переменные окружения процесса имеют приоритет. Справка работает без `.env` и ключей.

## Запуск

| Команда | Что делает |
| --- | --- |
| `npm run dev` | справка из исходников (TypeScript запускается Node.js напрямую) |
| `npm run dev -- doctor` | любая команда из исходников |
| `npm run build` | сборка в `dist/` и запуск собранной справки |
| `npm start` | справка из собранного `dist/` |
| `npm start -- doctor` | любая команда собранного приложения |

Неизвестная команда завершается с кодом 2.

## Диагностика

```bash
npm run doctor
```

`doctor` проверяет:

- версию Node.js (поддерживается 24.x);
- каждую настройку: «задано», «не задано», «некорректно» с причиной или значение по умолчанию для `DATA_DIR`, `APP_TIME_ZONE`, `LLM_MODEL`;
- для `GOOGLE_APPLICATION_CREDENTIALS` — что файл существует и доступен для чтения; содержимое не читается.

Значения выводятся только для `DATA_DIR`, `APP_TIME_ZONE` и `LLM_MODEL`; для ключей, токенов, id и пути к credentials показывается только статус. Соединения с Telegram, DeepSeek, TMDB и Google не проверяются: «задано» значит, что значение прошло локальную проверку формата.

Код завершения: 0 — всё задано и корректно; 1 — есть незаданные или некорректные настройки либо неподдерживаемый Node.js.

## Проверки

| Команда | Что делает |
| --- | --- |
| `npm run lint` | Biome без изменения файлов |
| `npm run lint:fix` | Biome с исправлением файлов |
| `npm run typecheck` | проверка типов без генерации файлов |
| `npm run check:deps` | архитектурные границы через dependency-cruiser |
| `npm test` | однократный запуск Vitest |
| `npm run test:watch` | Vitest в режиме наблюдения |
| `npm run test:coverage` | тесты с отчётом покрытия в `coverage/` |

CI (`.github/workflows/ci.yml`) на push и pull request выполняет `npm ci` и `npm run check` без секретов.

## Docker

```bash
docker compose build
```

```bash
docker compose run --rm series-scout
```

```bash
docker compose run --rm series-scout doctor
```

Образ собирается в два этапа: сборка с dev-зависимостями, затем production-образ только с production-зависимостями и `dist/`. Процесс работает от пользователя `node`; данные — в томе `series-scout-data`, смонтированном в `/data` (`DATA_DIR=/data`). Без аргументов контейнер выводит справку и завершается.

`.env` подключается, если он есть, но не обязателен. Секреты в образ не попадают. Файл Google credentials в контейнер пока не монтируется: если путь к нему задан в `.env`, `doctor` в контейнере покажет «файл не найден».
