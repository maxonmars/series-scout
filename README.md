# Series Scout

Персональный Telegram-бот для выбора сериалов и отслеживания премьер новых сезонов. Рассчитан на одного владельца.

## Назначение

- Интервью о предпочтениях и персональные рекомендации.
- Обратная связь по рекомендациям и список «Хочу посмотреть».
- Подписки на новые сезоны и периодическая проверка оригинальных дат премьер.
- Синхронизация премьер с отдельным Google-календарём.

AI работает в явном пайплайне: модель формирует профиль предпочтений и ранжирует реальных кандидатов из TMDB. Получение данных и внешние действия (запросы к TMDB, записи в календарь, сообщения в Telegram) выполняет код приложения.

## Текущее состояние

Реализовано и покрыто тестами с подменёнными внешними сервисами:

- Telegram-бот (long polling) только для владельца и только в личном чате; команды `/start`, `/profile`, `/recommend`, `/search`, `/list`, `/following`, `/sync`, `/status`, `/help`, `/about`;
- интервью на русском с подтверждением сериалов по карточкам TMDB, черновиком и подтверждением профиля; изменение профиля с отменой;
- подборка до трёх сериалов: кандидаты из TMDB (похожие, подходящие жанры, премьеры в ближайшие 180 дней), ранжирование и объяснения DeepSeek, проверка ответа модели;
- обратная связь: «В список», «Смотрел» с оценкой и пояснением, «Не интересно»; список «Хочу посмотреть»;
- подписки на новые сезоны, ежедневная проверка дат, уведомления о новой дате, переносе, исчезновении даты и премьере сегодня;
- события отдельного Google-календаря: создание, перенос, удаление при отписке и исчезновении даты;
- еженедельная подборка, планировщик с догоняющим запуском после простоя, очередь исходящих сообщений;
- SQLite с версионированием схемы, `doctor` и `doctor --network`, Docker-образ с постоянным томом.

С настоящими Telegram, TMDB, DeepSeek и Google Calendar локально проходит `doctor --network`, модель `deepseek-flash` доступна. Не проверены доступность API с целевого сервера, право сервисного аккаунта изменять события и качество рекомендаций на реальных профилях. В `/about` есть обязательная формулировка атрибуции TMDB, но нет логотипа TMDB.

## Требования

- Node.js 24 (точная версия — в [.nvmrc](.nvmrc); с nvm: `nvm use`).
- npm 11.
- Docker с Compose — для запуска в контейнере.

## Подключение сервисов

### Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и сохраните токен в `TELEGRAM_BOT_TOKEN`.
2. Узнайте свой числовой id (например, у [@userinfobot](https://t.me/userinfobot)) и сохраните в `TELEGRAM_OWNER_ID`.

Бот отвечает только этому пользователю и только в личном чате; сообщения остальных игнорируются без ответа.

### DeepSeek

Создайте API-ключ на [platform.deepseek.com](https://platform.deepseek.com) и сохраните в `DEEPSEEK_API_KEY`. Модель задаётся `LLM_MODEL`; `doctor --network` проверяет, что она есть в списке моделей, доступных ключу.

### TMDB

В [настройках API](https://www.themoviedb.org/settings/api) возьмите **API Read Access Token** (длинный JWT, не короткий API Key) и сохраните в `TMDB_READ_ACCESS_TOKEN`.

### Google Calendar

1. В [Google Cloud Console](https://console.cloud.google.com) создайте проект и включите Google Calendar API.
2. Создайте сервисный аккаунт и JSON-ключ к нему. Сохраните ключ в `secrets/google-service-account.json` (каталог исключён из Git).
3. В Google Calendar создайте **отдельный** календарь, например «Series Scout». Основной календарь бот не использует.
4. В настройках этого календаря откройте доступ адресу сервисного аккаунта (`…@….iam.gserviceaccount.com`) с правом «Внесение изменений в мероприятия».
5. В разделе «Интеграция календаря» скопируйте идентификатор календаря (`…@group.calendar.google.com`) в `GOOGLE_CALENDAR_ID`.

Календарь — представление состояния бота: события ведёт бот, ручные изменения управляемых событий может перезаписать следующая синхронизация. Отписываться от сериала нужно в боте.

## Установка и запуск из исходников

```bash
npm ci
```

```bash
cp .env.example .env
```

Пояснения к каждой настройке — в [.env.example](.env.example). Пустое значение считается незаданным. `.env` читается из рабочего каталога при запуске, если файл есть; переменные окружения процесса имеют приоритет.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | справка из исходников (TypeScript запускается Node.js напрямую) |
| `npm run dev -- run` | запуск бота из исходников |
| `npm run build` | сборка в `dist/` и запуск собранной справки |
| `npm start -- run` | запуск собранного бота |

Неизвестная команда завершается с кодом 2. `run` работает до `SIGTERM` или `SIGINT`: останавливает получение обновлений, дожидается текущего такта планировщика и закрывает базу. База — `series-scout.db` в `DATA_DIR`; второй процесс с той же базой не запустится.

## Диагностика

```bash
npm run doctor
```

```bash
npm run doctor -- --network
```

`doctor` проверяет без сетевых запросов:

- версию Node.js (поддерживается 24.x);
- каждую настройку: «задано», «не задано», «некорректно» с причиной или значение по умолчанию для `DATA_DIR`, `APP_TIME_ZONE`, `LLM_MODEL` и расписания;
- для `GOOGLE_APPLICATION_CREDENTIALS` — что файл существует и доступен для чтения; содержимое не читается.

Значения выводятся только для `DATA_DIR`, `APP_TIME_ZONE`, `LLM_MODEL`, `PREMIERE_CHECK_TIME`, `RECOMMENDATIONS_DAY`, `RECOMMENDATIONS_TIME`; для ключей, токенов, id и пути к credentials показывается только статус.

`doctor --network` после успешной локальной проверки выполняет только читающие запросы: Telegram `getMe`, TMDB `/authentication`, список моделей DeepSeek, список событий календаря. Право изменять события этим не проверяется — оно проявится при первой синхронизации.

Код завершения: 0 — всё в порядке; 1 — есть проблемы.

## Работа бота

| Команда | Что делает |
| --- | --- |
| `/start` | знакомство и интервью или его продолжение |
| `/profile` | профиль предпочтений и его изменение |
| `/recommend` | новая подборка до трёх сериалов |
| `/search название` | поиск сериала; без названия бот попросит его написать |
| `/list` | список «Хочу посмотреть» |
| `/following` | подписки, известные премьеры, отписка |
| `/sync` | немедленная проверка подписок и календаря |
| `/status` | последние результаты обращений к сервисам, заданий и очередей |
| `/help`, `/about` | справка, описание продукта и источники |

Расписание задаётся в `APP_TIME_ZONE` (по умолчанию `Asia/Novosibirsk`): проверка дат — ежедневно в `PREMIERE_CHECK_TIME` (09:00), подборка — в `RECOMMENDATIONS_DAY` в `RECOMMENDATIONS_TIME` (воскресенье, 18:00). После простоя каждое просроченное задание выполняется один раз; пропущенные напоминания за прошедшие даты не отправляются.

## Docker

Ключ сервисного аккаунта должен лежать в `secrets/google-service-account.json`: Compose подключает его как secret только для чтения в `/run/secrets/google-service-account` и сам задаёт `GOOGLE_APPLICATION_CREDENTIALS`. Процесс в контейнере работает от пользователя с UID 1000 — файл должен быть ему доступен для чтения (например, владелец с UID 1000 или права `644`).

```bash
docker compose build
```

```bash
docker compose run --rm series-scout doctor --network
```

```bash
docker compose up -d
```

```bash
docker compose logs -f series-scout
```

```bash
docker compose stop
```

Образ собирается в два этапа: сборка с dev-зависимостями, затем production-образ только с production-зависимостями, `dist/` и промптами. Без аргументов контейнер выполняет `run`; Compose перезапускает его после сбоя (`restart: unless-stopped`) и даёт 30 секунд на завершение по `SIGTERM`. Данные — в томе `series-scout_series-scout-data`, смонтированном в `/data`; пересоздание контейнера их не затрагивает. Запускайте один экземпляр сервиса. Секреты в образ не попадают, журнал заменяет известные значения секретов на `***`.

### Обновление

```bash
git pull
```

```bash
docker compose up -d --build
```

При запуске схема базы обновляется автоматически; база более новой версии, чем поддерживает приложение, не открывается.

### Резервное копирование и восстановление

Копируйте данные при остановленном контейнере.

```bash
docker compose stop
```

```bash
docker run --rm -v series-scout_series-scout-data:/data:ro -v "$PWD/backups:/backup" alpine tar czf /backup/series-scout-data.tar.gz -C /data .
```

```bash
docker compose start
```

Восстановление из архива (текущие данные тома заменяются):

```bash
docker compose stop
```

```bash
docker run --rm -v series-scout_series-scout-data:/data -v "$PWD/backups:/backup:ro" alpine sh -c 'rm -rf /data/* && tar xzf /backup/series-scout-data.tar.gz -C /data && chown -R 1000:1000 /data'
```

```bash
docker compose start
```

## Проверки

| Команда | Что делает |
| --- | --- |
| `npm run lint` | Biome без изменения файлов |
| `npm run lint:fix` | Biome с исправлением файлов |
| `npm run typecheck` | проверка типов без генерации файлов |
| `npm run check:deps` | архитектурные границы через dependency-cruiser |
| `npm test` | однократный запуск Vitest |
| `npm run test:watch` | Vitest в режиме наблюдения |
| `npm run test:coverage` | тесты с отчётом покрытия в `coverage/` |
| `npm run check` | lint, typecheck, check:deps, test и build |

Тесты не обращаются к сети: HTTP-транспорты, модель, Telegram API и календарь подменяются, базы создаются во временных каталогах. CI (`.github/workflows/ci.yml`) на push и pull request выполняет `npm ci` и `npm run check` без секретов.
